Устойчивость технологических профилей IT-ролей

Как меняются состав и порядок технологий в профиле роли, если по-другому считать долю, выбрать другой порог, исключить роль из фона или взять только тех, кто ответил на все вопросы.

Главный вопрос

Насколько устойчивы состав и порядок технологий в профилях семи IT-ролей к изменению метрики распространенности, порога отбора, фоновой совокупности и состава респондентов?

Что показал анализ

  • Внутри одной роли и одной категории доля респондентов p и доля упоминаний f различаются постоянным множителем, поэтому порядок технологий по ним совпадает полностью. Разница между 228 и 619 отобранными парами объясняется тем, что порог f ≥ 4% строже порога p ≥ 4% в 2,7–7,6 раза.
  • Логарифмический балл Slog = p·ln(1+L) почти повторяет порядок по распространенности: медианная корреляция Спирмена с p внутри категорий 0,941, с отношением L - 0,598.
  • Тесно коррелирующие правила по-разному устойчивы в верхней части рейтинга. Для Backend исходный объединенный top-10 сохраняется в 53,6% бутстреп-повторов для Slog, в 97,3% для p и в 99,0% для Sroot.
  • Исключение роли из собственного фона не меняет порядок по L внутри категорий; изменения комбинированных баллов малы (Спирмен ≥ 0,98).

Знаменатели и пороги

Одинаковое число - разные пороги

f = p / m, где m - среднее число вариантов, отмеченных одним ответившим. Поэтому условие f ≥ t равносильно p ≥ t·m: порог по упоминаниям строже порога по людям в m раз.

p = c / N    f = c / M    m = M / N   ⇒   f ≥ t  ⇔  p ≥ t·m

В ячейке: m / эквивалентный порог по людям p = t·m. Счет пар «роль - технология» ведется по всем 142 технологиям для семи ролей.

Сравнение правил

Насколько похожи рейтинги

Корреляции Спирмена между пятью правилами на одном отобранном наборе технологий и разложение дисперсии ln Slog на вклад распространенности и специфичности.

Матрица согласованности

Разложение Var(ln Slog)

Var(ln p)Var(ln ln(1+L))2·Cov

Доли делятся на общую дисперсию. При отрицательной ковариации доля Var(ln p) может превышать 1. Это алгебраическое разложение, а не причинные вклады.

Устойчивость

Что сохраняется при пересчетах

Доля бутстреп-повторов, в которых исходный top-10 сохранился полностью (с учетом связанных рангов, без учета внутреннего порядка), а также влияние фона и полноты ответов.

Стандартная ошибка Монте-Карло для доли при 1 000 повторах не превышает 0,016. Интервалы условны на наблюдаемые размеры страт DevType.

Фон и полнота ответов

Сравнение с полными ответами не выравнивает размер выборки: различия отражают одновременно меньший объем и другой состав респондентов.

Данные и методика

Как получены числа

Все значения на сайте посчитаны скриптом run_analysis.py по файлу опроса с фиксированной контрольной суммой.

Формулы

p(r,s) = c(r,s) / N(r,k)     f(r,s) = c(r,s) / M(r,k)
L(r,s) = p(r,s) / p(all,s)
Slog = p·ln(1+L)     Sroot = p·√L     Slin = p·L

c - число респондентов роли r, отметивших технологию s; N - число ответивших на вопрос категории k; M - общее число отмеченных вариантов в этом вопросе. Фон «все ответившие» включает текущую роль, вариант «без текущей роли» исключает ее из числителя и знаменателя.

Воспроизведение

pip install -r requirements.txt
python run_analysis.py --csv survey_results_public.csv \
  --saved skill_weights_by_role_final_v2.csv --out results \
  --bootstrap 1000 --seed 2026

Ограничения

Опрос основан на самоотборе участников и самоотчете. Семь ролей унаследованы от прикладного проекта карьерной платформы и не исчерпывают IT-профессии. Бутстреп оценивает неопределенность внутри наблюдаемого файла, но не исправляет смещения выборки. Внешней проверки профилей по вакансиям или экспертным оценкам в этой версии нет.
